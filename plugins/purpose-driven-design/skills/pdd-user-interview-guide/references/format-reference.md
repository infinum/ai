# Interview Guide Format Reference

All Infinum/ETR interview guides follow a consistent document structure and visual style. Match these conventions exactly in every output.

---

## Document Header

```
[Document Title — e.g. "User Interview Script" or "User Interview / Usability Test Guide"]
[Client Name] | [Month Year]
```

Include the ETR / Infinum logo placeholder (omit in Markdown; included in PDF output).
Add the horizontal rule divider below the header.

---

## Section Order

1. **What are we trying to learn?** *(internal — bullet list of research questions)*
2. **Who do we want to talk to?** *(participant profiles with screening criteria per segment)*
3. **Recruitment Plan** *(platform, approach, logistics, incentives)*
4. **Screener Questions** *(numbered, with branching logic where needed)*
5. **Intro Script** *(verbatim text the researcher reads aloud)*
6. **Interview Questions** *(organized into named subsections with a clear flow)*
   - Optionally: **Usability Test Tasks** *(if a usability component is included)*
7. **Wrap-Up** *(standard closing lines + final open question)*

---

## Section Naming Conventions

Use these exact headings (adapt slightly for context):

- `What are we trying to learn?`
- `Who do we want to talk to?` (or `Setup` for simpler documents)
- `Screener` (or `Screening Requirements` / `Screener Questions`)
- `Intro Script`
- `Interview Questions`
- `Tasks` (for usability sections)
- `Wrap-Up`

---

## Question Formatting

- Use numbered lists for screener questions and interview questions.
- Use lettered sub-items (a, b, c…) for follow-up probes under a main question.
- Keep all questions in normal weight — don't bold them (only headings are bold).
- Use italics for interviewer notes, conditional logic, and instructions: *(If they've used services in the past, ask…)*
- Keep each question to one sentence where possible.
- Write questions in plain, conversational language.

---

## Intro Script Style

- First-person, warm, casual tone: "Thanks so much for taking the time…"
- State: your name, why you're doing this research, what the session will involve.
- Emphasise no right or wrong answers.
- Ask for recording permission.
- Leave space for participant questions.

---

## Conditional / Branching Logic

Use italics with parentheses to indicate conditions:

*(If they're seeking support for their child)*
*(If they've used the product before)*
*(For B2B participants only)*
*(Only ask if they didn't mention X earlier)*

---

## Usability Task Format

When usability tasks are included, add them after the interview questions as a separate section. Use a brief task script intro, then number each task. Include follow-up probes in lettered sub-items.

Example:
```
For this next part, I'd like you to share your screen as we take a look at [product/website]. 
Please try to think out loud as much as possible. Any questions before we get started?

1. [Task instruction]
   a. [Follow-up probe]
   b. [Follow-up probe]
```

---

## Tone & Length Guidelines

- Total interview guide: 2–5 pages for a standard guide, up to 8 pages for multi-segment studies.
- Screener: 3–6 questions max. Keep it short — respondents abandon long screeners.
- Interview questions: 15–25 total across all sections for a 30–45 min session.
- Incentive guidance by session length:
  - 30 min: $30–$40
  - 45 min: $50–$60
  - 60 min: $75–$100
  - 90 min: $100–$125
  - Add 50% recruiting fee when using Respondent.io or User Interviews

---

## Recruitment Platform Defaults

- **Respondent.io** — preferred for B2C and general consumer research; include headline and screener parameters. The platform handles scheduling and reminder emails, so **don't include a reminder-email step** for these participants.
- **User Interviews** — alternative to Respondent.io for similar use cases. Like Respondent.io, it handles scheduling and reminders, so no reminder email is needed from us.
- **Client-sourced participants** — for existing customers / stakeholders; note this in the recruitment section and flag potential bias. (Only client-sourced participants need outreach/reminder emails from our side.)
- **Mix** — for studies needing both current customers and prospective/unbiased users.

- Bold section headings, normal weight body text
