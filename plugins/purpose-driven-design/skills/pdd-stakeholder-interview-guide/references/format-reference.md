# Stakeholder Interview Guide — Format Reference

All Infinum/ETR stakeholder interview guides follow the same visual conventions as user interview guides,
with structural differences that reflect the internal-facing nature of stakeholder sessions.

---

## Document Header

```
Stakeholder Interviews
[Client Name] | [Month Year]
```

Include ETR / Infinum branding (∞ INFINUM top-right header on every page).
Add the red horizontal rule divider below the title.

---

## Section Order

1. **Participant List** *(names and titles of all planned interviewees — appears at the top, before the intro)*
2. **Intro Script** *(verbatim text the researcher reads at the start of each session)*
3. **Per-Participant Question Sets** *(one named section per person or role group)*
   - Each section: participant name + title as heading, then numbered interview questions organized into subsections
4. **Wrap-Up Line** *(standard closing question, repeated after each participant's questions)*

**Note:** Stakeholder guides do NOT have a screener, recruitment plan, or "Who do we want to talk to?" section —
participants are internal client team members, not recruited externally.

---

## Key Structural Differences from User Interview Guides

| User Interview Guide | Stakeholder Interview Guide |
|---|---|
| Has screener + recruitment plan | No screener; participants are pre-selected |
| One question set for all participants | Separate tailored question set per role |
| "What are we trying to learn?" section | Omit — internal planning artifact only; not needed in the deliverable |
| Generic intro script | Intro acknowledges interviewer's role on the project team |
| Organized by research topic | Organized by participant role, then subsection |

---

## Participant List (top of document)

List all planned interviewees at the very top, before the intro script:
```
[Name]: [Title]
[Name]: [Title]
```

Group primary stakeholders (senior leadership, product owners) first, then secondary.
Leave a blank line between the two groups visually if needed.

---

## Intro Script Style

- First-person, warm, professional — slightly more formal than a user interview intro
- Name the interviewer(s) and their role on the project
- State the goal: to hear from them, shape the project, understand their perspective
- Acknowledge the session length and flexibility
- Mention recording + confidentiality
- End with: "Any questions before we get started?"

Standard notes bullets (example):
- Recording consent
- Session length flexibility (end early or follow up)
- Invitation to add anything after the session

---

## Per-Participant Question Sets

Each section:
- **Heading**: Participant name + title (H2 level)
- **Sub-heading**: "Interview Questions" (H3 level, or just start numbered list)
- Numbered questions, organized into **named subsections** (H3):
  - Background / Role
  - Context
  - Users
  - Content
  - Tech & Features *(if relevant to role)*
  - Risk & Concerns
  - Competitors
- Keep all questions in normal weight — don't bold them (only headings are bold)
- Use *italics* for conditional notes or interviewer instructions: *(Ask only if they haven't already addressed this)*
- Use lettered sub-items (a. b. c.) for follow-up probes
- End each participant's section with the standard wrap-up line

---

## Subsection Defaults by Role

**Executive / Leadership (CEO, CCO, CTO)**
Background → Context & Goals → Users → Content → Tech (minimal) → Risk → Competitors → Ideas

**Clinical / VP of Services**
Background → Context → Users (deep) → Clinical Content → Services → Risk → Competitors

**Marketing / Growth**
Background → Context → Users → Content & SEO → Channels → Tech features → Risk → Competitors

**Operations / Technology**
Background → Context → Users (brief) → Tech Constraints → Integrations → Workflow → Risk

**Business Development / Sales**
Background → Context → Users (funnel focus) → B2B → Content → Risk → Competitors

---

## Question Count Guidelines

Stakeholder interviews are typically 45–60 minutes. Scale question count to session length only:

- 30 min → 15–20 questions
- 45 min → 20–28 questions
- 60 min → 28–38 questions
- Group session (60–90 min, multiple participants) → 35–50 questions total

---

## Wrap-Up Line

End every participant's section with:
> "Is there anything else you think we should know that we haven't talked about yet in this session?"

Optionally add:
> "Is there anyone else you think we should talk to?"

---

## Tone Notes

- More professional than user interviews, but still conversational — not stiff
- Acknowledge their expertise: "You know this organization better than anyone…"
- It's fine to reference what other stakeholders said or what came up in a prior workshop — "I know we touched on this in the discovery workshop, but…"
- Avoid leading questions that telegraph what answer you expect
- For sensitive topics (budget, org politics, concerns about the project): frame neutrally — "What keeps you up at night about this?" not "Are you worried about…?"
